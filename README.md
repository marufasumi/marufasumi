## 1. 💊 PharmacologyGPT — Hybrid RAG Application

<p>
  <a href="https://github.com/marufasumi/PharmacologyGPT-RAG">
    <img src="https://img.shields.io/badge/View%20Repository-181717?style=for-the-badge&logo=github&logoColor=white" />
  </a>
  <a href="https://pharmacologygpt.streamlit.app">
    <img src="https://img.shields.io/badge/Live%20Application-FF4B4B?style=for-the-badge&logo=streamlit&logoColor=white" />
  </a>
</p>

**PharmacologyGPT** is a production-oriented Retrieval-Augmented Generation application designed to answer pharmacology questions using a combination of trusted textbook knowledge and current web information.

### Why I built it

Pharmacology information is complex, highly technical, and often distributed across large reference books and online sources. This project explores how hybrid retrieval and intelligent routing can improve answer relevance while preserving source awareness.

### Core architecture

```text
User Question
      |
      v
Query Intent Classification
      |
      v
Query Rewriting
      |
      v
Routing Decision
  /       |       \
Local     Both     Web
  |        |        |
  v        v        v
Dense    Hybrid    Tavily
Search   Search     Search
  \        |        /
   \       v       /
    Context Fusion
          |
          v
   GPT Answer Generation
          |
          v
 Answer + Source Context
```

### Key features

- Ingests and processes large pharmacology PDF textbooks
- Stores document chunks in ChromaDB
- Uses OpenAI embeddings
- Combines dense retrieval with BM25 keyword retrieval
- Uses Maximum Marginal Relevance for diverse context selection
- Applies Reciprocal Rank Fusion to merge retrieval results
- Classifies user intent before retrieval
- Rewrites vague or incomplete questions
- Routes questions to local documents, web search, or both
- Uses Tavily for current web information
- Provides a modular Streamlit interface
- Includes tests for retrieval, routing, query rewriting, and web search
- Uses lazy loading and deployment-oriented dependency management

### Scale

- Approximately 3,081 source pages
- Approximately 17,879 vectorized document chunks
- Five major pharmacology reference documents
- Modular retrieval, routing, fusion, and generation layers

### Technology stack

`Python` • `LangChain` • `OpenAI` • `ChromaDB` • `BM25` • `RRF` • `Tavily` • `Streamlit` • `PyPDF`

## 2. 💊 FAERS Pharmacovigilance & Drug Safety Analytics Platform

**Project focus:** Predicting serious adverse drug events using FDA FAERS data and statistical learning methods.

This end-to-end healthcare analytics project transforms raw FDA Adverse Event Reporting System data into a report-level analytical dataset and applies exploratory analysis, statistical testing, clustering, and supervised machine learning.

### Business and healthcare objective

The project investigates whether demographic, drug, reaction, indication, reporter, and therapy-related characteristics can help identify reports associated with serious adverse outcomes.

### Data engineering workflow

```text
FDA FAERS ASCII Tables
        |
        v
DEMO • DRUG • REAC • OUTC • THER • INDI • RPSR
        |
        v
Cleaning and Standardization
        |
        v
Table-Level Aggregation
        |
        v
One Row per FAERS Report
        |
        v
Feature Engineering
        |
        v
EDA + Statistical Testing
        |
        v
Clustering + Supervised Modeling
        |
        v
Interactive Streamlit Analytics Application
```

### Dataset scale

- 406,184 adverse-event reports
- 1,909,327 drug records
- 1,445,416 reaction records
- 1,186,115 indication records
- 594,449 therapy records
- 295,044 outcome records
- 51-column analytical dataset
- One modeling row per FAERS primary report

### Analytical components

- Demographic analysis
- Missing-data assessment
- Drug-burden analysis
- Reaction-burden analysis
- Indication and comorbidity flags
- Therapy-duration features
- Welch's t-tests
- Mann–Whitney U tests
- Chi-square tests
- K-Means clustering
- Classification modeling
- Cross-validation
- Hyperparameter tuning
- Model evaluation and comparison

### Models evaluated

- Logistic Regression
- Linear Discriminant Analysis
- Quadratic Discriminant Analysis
- Gaussian Naive Bayes
- K-Nearest Neighbors
- Support Vector Machine
- Decision Tree
- Random Forest
- Neural Network

### Best model

**Random Forest**

- Accuracy: **92.58%**
- ROC-AUC: **96.85%**
- F1-score: **93.25%**
- Cross-validation accuracy: **92.44%**

### Application features

- Executive overview
- Exploratory data analysis
- Statistical analysis
- Machine learning comparison
- Clustering analysis
- Serious-event prediction interface
- Reusable data-loading and prediction utilities

### Technology stack

`Python` • `Pandas` • `NumPy` • `SciPy` • `scikit-learn` • `Streamlit` • `Plotly` • `Joblib`
